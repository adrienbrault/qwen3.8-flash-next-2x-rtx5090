# The served image, layer by layer

The served configuration on `:8022` runs `tabbyapi:mtp-pruned-r1` (since 2026-09-19 05:16 CEST, [R528](../bench/results/r528-promote-mtp-pruned.md)), built on `tabbyapi:stack-r4-e3r2`. Up to `-moecoopv2` the tag is the build history: each suffix is one layer built on the previous one. From there each overlay directory carries its own `Dockerfile.box` with `ARG BASE=<previous image>`. Provenance and licences for every input are in [`../THIRD_PARTY.md`](../THIRD_PARTY.md); the measurement that admitted each layer is linked in the last column and indexed in [`../bench/RESULTS.md`](../bench/RESULTS.md).

Every layer above was admitted with byte-identical greedy output on the c1 256-token and 30k prompts (the fingerprints are in each result file), except where the layer only changes rows ≥ 9 (bszn16, coopwide at ≥ 128 slots), where the gate was GSM8K and tool-eval under concurrency instead, and E3, which changes the 30k fingerprint through the prefill accumulation order and was gated on GSM8K, needles and tool-eval.

Rebuild order: `Dockerfile.tabbyapi` → `-qsa-cid` → `-pr337` → `-bszn` ×3 (bszn16, coopwide, hc-mix-v2-r2) → `-pyfile` (hostgap) → `-pypatch` (ppipe) → the three overlays in order, then `decode-kernels-r2` → `refbase` → `decode-kernels-r4` → `stack-r4-e3r2` → `mtp-pruned-r1` (`docker build --build-arg BASE=<previous tag> -f overlays/<name>/Dockerfile overlays/<name>` for the first two; the MoE overlay's build context is the overlay's parent and it takes `--build-arg BASE=<tag>`, not an image id). The Dockerfiles pin TabbyAPI by SHA and ExLlamaV3 by version and assert both at build time.
