# tune268-r2

Build `tabbyapi:tune268-r2` on `tabbyapi:tune268-r1` with `bash docker/overlays/tune268-r2/build.sh`, or run `bash docker/build-chain.sh` from the repository root. `BASE`, `TAG`, `DOCKER` and `MAX_JOBS` override the standalone build. The Dockerfile verifies the patch SHA256, applies it at fuzz 0, rebuilds the image's native extension with its existing `rebuild-native.py`, imports it and rejects changes to the predecessor's SASS. The build uses no GPU and disables network access.

Round 2 adds K2.5 E3 grouped prefill, a fixed histogram path, fixed-K2.5 fused prefill instances and uncapped batch-one gate/up instances. All four selectors default to 0 in the image: `EXL3_MOE_PREFILL_E3_HALF`, `EXL3_MOE_PREFILL_HALF_HIST`, `EXL3_MOE_PREFILL_HALF_STATIC` and `EXL3_MOE_COOP_HALF_A_UNCAP`. The served launcher sets only `EXL3_MOE_PREFILL_E3_HALF=1`; it also retains round 1's two enabled selectors and `EXL3_MOE_PREFILL_E3_DET=1`. E3 HALF changes prefill accumulation order relative to the fused fallback; the other three paths require bitwise parity. The original build preserved every round-1 function and added 14 kernels. Round-2 bitwise checks passed 380/380 and the E3 HALF numerical gate passed 792/792.

The installed-source recipe is reproduced by this chain; rebuilding produces a different image ID. The launcher pins the measured operator build and requires a reviewed pin update before a rebuilt image can serve. Promotion measurements and their conditions are in [publish268-served-268](../../../bench/results/publish268-served-268.md).
