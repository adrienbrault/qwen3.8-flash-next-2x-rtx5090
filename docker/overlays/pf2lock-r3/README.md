# pf2lock-r3

Build `tabbyapi:tune268-r2-pf2lock-r3` on `tabbyapi:tune268-r2` with `bash docker/overlays/pf2lock-r3/build.sh`, or run `bash docker/build-chain.sh` from the repository root. `BASE`, `TAG` and `DOCKER` override the standalone build. The Dockerfile verifies the SHA256 of `pf2lock.patch` and of the module before and after the patch, applies the patch at fuzz 0 to the installed `exllamav3/modules/ngram_embedding.py`, asserts that the native extension is byte-identical to the base's, then runs the CPU stress scenarios `share`, `steady` and `long` with `EXL3_NGRAM_PREFETCH2=1` and `offpath` with it unset (5,000 iterations each, zero failures required) and the 24 deterministic tests in `pf2lock_tests.py`, and imports the patched module. The build uses no GPU and disables network access.

The patch fixes a race in the served `EXL3_NGRAM_PREFETCH2` path of `ngram-prefetch-r1`. The prefetch worker's deferred staging and the issuing thread's inline staging on a lookup miss both chose a free pinned staging set before either marked it held, so both could write one set and one forward could return the other's n-gram embedding rows. The same unguarded state let a retire cancel an entry a forward had just matched (`CancelledError`), let the worker read an entry before its future existed, and raised `IndexError` when no free set remained after a retire. Failure paths could also leave a set held. Round 1 adds a `threading.Lock` that makes set selection and the held mark one step and guards `_pending` membership. Round 2 gives every held set one owner that releases it on every path, failures included: `_PinSet.grow` allocates all four buffers before assigning any, a failed growth returns the reservation, a retired or abandoned entry releases its set only after its future has finished, and a set whose uploads cannot be fenced by an event is discarded instead of reused. Round 3 adds a per-entry commit/abort gate, so a task queued by a `submit()` that then raised touches no staging set. The lock is never held across a future wait, an event synchronize, a poll sleep or an allocation. The contract is one issuing thread per module at a time, with the prefetch worker as the only concurrent party; the served generator and prefill pipeline meet it. The rows, their order and the arithmetic are unchanged when no race occurs.

`build-manifest.json` is the record of the operator build that produced the served image `sha256:da386167cc762f08763a3ab41d98e50403504790b4495053d568f70e61432021`: base `sha256:2239954c…`, patch `13a892c1…`, module `b9b227f8…` → `e04ef253…`, extension `.so` unchanged, the four stress scenarios at 5,000/5,000 and the 24 tests passing, and an installed-tree comparison against the base whose only difference is the patched module. Its recipe hashes for `pf2lock.patch`, `cpu_stress.py`, `pf2lock_harness.py` and `pf2lock_tests.py` match the files here. The operator `Dockerfile` pinned `BASE` to the image ID and had a longer header; its `FROM` line and everything after it are identical to this one. Rebuilding produces a different image ID; the launcher pins the measured build and requires a reviewed pin update before a rebuilt image can serve. Gate measurements and conditions are in [pf2lock-r3](../../../bench/results/pf2lock-r3-race-fix.md).
