# Experimental ExLlamaV3 1.6.4 rebase

Prepared 2026-10-21. The served image and checkpoint remain unchanged. This packet pins ExLlamaV3 1.6.4, a compatible TabbyAPI commit and the official Python 3.12/CUDA 12.8/Torch 2.9.0 wheel. It carries server fixes and the batch-indexed MTP selector while using the new upstream kernels and scheduler. [PATCH-AUDIT.md](PATCH-AUDIT.md) distinguishes retained code from native replacements and known differences. No performance or accuracy gain is established by the source port alone.

Run `bash build.sh` on the Linux host containing the exact parent image. `prepare.py` verifies upstream archive and wheel SHA256 values before applying the source patches; the build runs CPU import, result-handler and draft-schema checks. The output is a candidate image, never an installed serving configuration. The checkpoint manifests pin both self-calibrated 2.18 and 2.68 bpw revisions for later comparison against the existing 2.50 bpw pack.

Performance repair2026-10-21 adds default-off draft-head pruning (`EXL3_MTP_HEAD_N=65536`), ordered eight-row MoE microbatches (`EXL3_MOE_DECODE_CHUNKS=1`) and native fused mixers through32rows (`EXL3_GR_DECODE_ROWS32=1`). The official native wheel and its eight-row BC capacity remain unchanged. The [control measurements](../../../bench/results/flashnext-rebase-repair.md) locate an MTP verification path change above eight rows. These ports are experimental; the served configuration remains unchanged. The image build exercises native fallback/cropping/confidence, prefix-cache lifecycle and BC scratch-alias regressions on Linux. The exact same-prefix native-API check passes on GPU at1–8rows; full-forward prefix logits can differ by0.1455 at one row. This is not full-vocabulary parity or task accuracy qualification.

`build-native.sh` builds the experimental source-native recovery with32-row Python/C++ capacities and carried MoE/mixer kernels. It verifies the same manifest and applies `native.patch` after `engine.patch`. `EXL3_MOE_COOP_V2=1 EXL3_MOE_COOP_V3=3 EXL3_MOE_COOP_ROWS32=1` opts into integer sm120 MoE kernels; half-integer rates use upstream fallback. `EXL3_GR_LEGACY_INT8=1` selects the prior daily mixer at H4, hidden2560, rank320 for decode through32rows. Native prefill remains unchanged. These numerics-changing selections are default off; the compiled32-row capacity is part of the experimental image. Full performance and task accuracy checks remain pending.

Default-off `EXL3_PREFILL_COMPAT=1` sets native `shared_chunk_size=max_chunk_size` and `prefill_cooldown=0` at generator construction. It selects existing native scheduler behavior; it does not port the old two-device lookahead pipeline. OFF preserves upstream defaults. A same-image six-agent comparison is pending. `Dockerfile.prefill-policy` is an incremental Python-only build from the exact corrected native image; the full native recipe includes the same source change through `engine.patch`.
